# Project Overview

## The game

**Dead Spin** is a single-player, first-person 3D casino survival game with psychological
horror and roguelite progression. The player wakes inside an underground casino owing
$50,000 to the Game Master and has 18 rounds of roulette to pay it off.

The Game Master can rewrite the game: add, remove, duplicate and rearrange pockets, change
the wheel's size, alter payouts, shake the table and impose new rules. He must always leave a
legitimate path to winning. The player survives through probability, money management,
abilities bought with Influence, and loopholes in the Game Master's rules.

Design pillars: **gambling strategy**, **adaptation**, **survival**.
Platform: Windows PC, keyboard and mouse first. All money is fictional.

## Current implementation (Phase 1: Foundation)

Working now:
- First-person movement (walk, sprint, gravity) and smoothed mouse look.
- Interaction: crosshair targeting while walking, cursor pointing while seated, focus
  highlight, inspection text.
- A procedurally generated greybox roulette room: marble floor, velvet walls, wood panelling,
  gold trim, pillars, chandeliers, wall sconces, fog, a warm spotlight on the table.
- A roulette table placeholder with wheel, betting layout grid, chip tray and a seat.
- Sitting at the table glides the camera to a table view and frees the cursor; standing up
  returns control.
- Four sealed doors to future rooms and the silent Game Master figure, all inspectable.
- Game modes (exploring, at table, paused, run ended) with a validated state machine.
- Run state: $2,500 balance, $50,000 debt, 18 rounds, minimum bet, all configurable via a
  `RunConfig` ScriptableObject.
- Ledger with full transaction history; bankruptcy, freedom and deadline outcomes.
- Round phase flow (announce, betting countdown, closed, spin, resolve, summary), ready for
  the spin system in Phase 2.
- HUD with balance, debt, round, prompts, pause menu, end-of-run screen and a developer panel.

Not yet implemented: the roulette wheel, ball and betting (Phase 2), dynamic wheels
(Phase 3), chips (Phase 4), the Game Master's interventions (Phase 5), and everything after.
See [DEVELOPMENT_ROADMAP.md](DEVELOPMENT_ROADMAP.md).

## Design decisions so far

| Decision | Reason |
|---|---|
| Money is whole dollars stored as `long`; fractional payouts round down (house favour) | Exact arithmetic, no floating-point drift in the economy |
| A run is lost to bankruptcy only when no money is on the table and the balance is below the minimum bet | Players with chips still in play may yet win |
| Bankruptcy checks wait until a spin has resolved | Winnings must land before the house can declare ruin |
| Pause returns only to the mode it interrupted | Prevents pause from being used to skip state rules |
| Prototype scene is generated by an editor command | No hand-edited scene YAML, rebuildable at any time |
| IMGUI for the Phase 1 HUD | No prefab or package dependencies; replaced in Phase 8 |
